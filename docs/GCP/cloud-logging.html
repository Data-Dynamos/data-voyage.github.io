Cloud Logging

Overview​

Cloud Logging is Google Cloud's managed logging service.

It collects and provides access to logs generated by:

  • Google Cloud services
  • Applications
  • Infrastructure
  • Containers
  • Kubernetes workloads
  • Other supported sources

A useful observability model is:

Logs
  ↓
Search / Troubleshoot
  ↓
Analyze
  ↓
Metrics
  ↓
Alerts / Dashboards

Learning objectives​

Understand:

  • Log search
  • Log analysis
  • Log-based metrics
  • Audit logs
  • Log routing/export

1. Log entries​

A log entry contains information about an event.

Typical fields include:

  • Timestamp
  • Severity
  • Resource
  • Log name
  • Message/payload
  • Trace information
  • Labels
  • Authentication/request metadata where applicable

2. Log search​

Use Logs Explorer to search and troubleshoot.

Example query:

severity>=ERROR

Example:

resource.type="dataflow_step"
severity>=ERROR

Queries use the Cloud Logging query language.

Typical search dimensions:

resource
severity
timestamp
logName
labels
jsonPayload
protoPayload

3. Log analysis​

Logs Explorer is useful for troubleshooting individual log entries and sequences.

For aggregation and analytical queries, Google Cloud provides log analytics capabilities.

Example questions:

  • How many errors occurred per hour?
  • Which service generated most errors?
  • What is the distribution of request latency?
  • Which job generated a specific failure?

Conceptually:

Raw logs
   ↓
Filter
   ↓
Aggregate
   ↓
Trend / chart

4. Log-based metrics​

A log-based metric converts matching log entries into a metric.

Example:

Log:
ERROR payment failed

       ↓

Log-based metric:
payment_failure_count = 1

The metric can then be used in Cloud Monitoring.

Types include:

  • Counter
  • Distribution
  • Boolean/system-defined metric types

Example architecture:

Application logs
       ↓
Cloud Logging
       ↓
Log-based metric
       ↓
Cloud Monitoring
       ↓
Alert

5. Audit logs​

Cloud Audit Logs answer:

Who did what, where, and when?

Major categories include:

  • Admin Activity
  • Data Access
  • System Event
  • Policy Denied

Example:

User/service account
        ↓
Changed BigQuery IAM
        ↓
Audit log
        ↓
Cloud Logging

Audit logs are important for:

  • Security
  • Compliance
  • Troubleshooting
  • Investigations
  • Governance

6. Log routing and exports​

Cloud Logging can route logs using log sinks.

Typical destinations include:

  • Log buckets
  • Cloud Storage
  • BigQuery
  • Pub/Sub
  • Other supported destinations

Example:

Cloud Logging
      |
      +---- BigQuery  → analytics
      |
      +---- GCS       → archive
      |
      +---- Pub/Sub   → external processing

A sink contains filters that determine which logs are routed.

Example conceptual filter:

severity>=ERROR

7. Cloud Logging + BigQuery​

A common enterprise pattern is:

Application / GCP logs
        ↓
Cloud Logging
        ↓
Log sink
        ↓
BigQuery
        ↓
SQL analytics

This allows logs to be joined with business or operational data.

8. Cloud Logging + Monitoring​

A useful operational pattern is:

Log
 ↓
Log-based metric
 ↓
Monitoring
 ↓
Alert

For example:

Dataflow job emits ERROR
        ↓
Logging filter matches
        ↓
error_count metric increases
        ↓
Monitoring threshold exceeded
        ↓
Notification
